# Contributing to waaseyaa.org

This repository is the Waaseyaa framework's public documentation site: a
Waaseyaa application serving the framework's spec corpus as HTML, Markdown,
and a read-only MCP endpoint, plus a grounded docs chat.

## Development

```bash
composer install
touch storage/waaseyaa.sqlite
APP_ENV=local php vendor/bin/waaseyaa db:init
APP_ENV=local php -S 127.0.0.1:8098 -t public public/index.php
```

## Before you open a pull request

All of these run in CI; run them locally first:

```bash
composer validate --strict
vendor/bin/phpunit                                   # must stay green
vendor/bin/phpstan analyse                           # level 6, no errors
PHP_CS_FIXER_IGNORE_ENV=1 vendor/bin/php-cs-fixer fix
php bin/sync-specs.php && git diff --exit-code resources/specs
```

House rules:

- No em dashes in site copy, ever (enforced by `ContentHonestyTest` and CI).
- No marketing language the product cannot back; the framework is alpha and
  the site says so plainly.
- `resources/specs/` is generated by `bin/sync-specs.php`; never hand-edit.
- The `/start` walkthrough's code samples are mirrored by
  `tests/Tutorial/TodoAppTest.php`. Change them together or CI fails.
- Never work around a framework defect in app code. Produce a minimal
  reproduction, file it on `waaseyaa/framework`, and reference the issue.

## Dependency policy

The `waaseyaa/*` packages are pinned to an exact alpha version in
`composer.json`. A routine `composer update` must never float the framework
line: framework upgrades arrive as dedicated pull requests containing

1. the constraint bump and full `composer.lock` diff,
2. a re-synced spec corpus (`php bin/sync-specs.php`),
3. a green test suite and production-shaped container smoke run,
4. deploy notes covering any new boot requirements.

Every past production incident on this site came from a framework version
change; that is why the pin is exact and the upgrade path is a reviewed PR.

Non-framework dependencies are updated by Dependabot PRs, which get the
same CI gates.

## Deploys

Deploys are cut from `main` via `waaseyaa-infra` (pinned commit, rebuilt
container on the Pi). Nothing in this repository deploys itself. Do not
deploy without Russell's explicit go.
